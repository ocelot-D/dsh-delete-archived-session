## dsh-delete-archived-session

一个 DSH 插件：**列出并删除已归档的会话**。

DSH 本身只有「归档」和「取消归档」两个操作。**归档只是把会话藏起来，日志永远留在磁盘上**，官方没有任何办法把那块空间收回来。

这个插件补上缺失的那一半。它提供两个入口：

| 入口 | 名字 | 用途 |
|---|---|---|
| 工具（给 AI 用） | `delete_archived_sessions` | `action:"list"` 列出所有归档会话；`action:"delete"` 删除指定的 |
| 斜杠命令（给你用） | `/delete-archived` | 同样的功能，在输入框里打 |

```
/delete-archived list
/delete-archived delete 11111111-2222-3333-4444-555555555555 --yes
/delete-archived delete <会话ID> <会话ID> --yes --permanent
```

### 安全设计

删会话就是把聊天记录销毁掉，所以这个插件刻意做得很保守。下面每一条都写在代码里，并且有测试覆盖：

1. **只能删已归档的。** 只有出现在归档列表里的会话才能操作。没归档的会被拒绝，绝不动它。

2. **必须明确确认。** 删除要同时满足：给出准确的会话 ID，并且带上 `confirm: true`（工具）或 `--yes`（命令）。只打 `/delete-archived delete <ID>` 不带 `--yes`，它会拒绝，并把该重新执行的完整命令打印给你。

3. **必须先证明归属。** 动手之前会先读那个会话自己日志的第一行，确认里面的 `id` 和你要删的完全一致。如果目录里装的是别人的日志，或者根本没有日志，一律拒绝——这是防止"名字撞车"误删别的东西。

4. **不许跑出根目录。** 算出来的会话目录必须严格位于会话根目录之内，任何路径都逃不出去。

5. **默认可以恢复。** 删除默认是**把文件夹移进回收站**，不是真删。只有加 `permanent: true` / `--permanent` 才会真正抹掉。移进回收站时会**保留原有的「项目目录/会话目录」名字**，只是多套一层带时间戳的批次文件夹：

   ```
   会话库/<项目目录>/<会话目录>  →  回收站/<时间戳>/<项目目录>/<会话目录>
   ```

   保留这两层名字是关键——DSH 就是靠这个名字找会话的，改名的话日志虽然还在，但会话就再也找不回来了。移回去 = 恢复。

   如果回收站设在了别的磁盘分区，会直接报错，而不是偷偷变成一次可能半途而废的复制。

6. **顺手清掉归档记录。** 删除成功后会把该 ID 从归档列表里移除，这样界面就不会再列一个日志已经没了的会话。如果磁盘上压根没日志（残留记录），也会把这条记录清掉。

7. **绝不把 DSH 搞崩。** 压缩日志是通过流式解压读取的，并且显式挂了错误处理，失败时回退到有上限的整块解码。正在写入的会话日志可能出现"撕裂帧"，这种情况必须表现为"拒绝删除"，而不能变成一个没人接的流错误——那在 DSH 主进程里是会直接崩掉的。

### 安装

这是一个标准的 DSH 插件包：`package.json` 里声明了 `dsh.bundle.patch`，`cordis.patch.yml` 负责插入一行。

**方法一（推荐）**：在对话里说一句「把这个插件装上」，让 AI 调用插件管理器安装。

**方法二**：自己手动加。在 profile 的 `package.json` 里加依赖并登记 bundle：

```json
{
  "dependencies": { "dsh-delete-archived-session": "file:./dsh-delete-archived-session" },
  "dsh": { "profile": { "bundles": ["dsh-delete-archived-session"] } }
}
```

装好后需要重启 DSH 才生效。

### 配置

插件**不导入 Node 标准库以外的任何东西**——它注册的是朴素的工具/命令描述对象，也不接受 schemastery 的 `Config`。这样做是为了不管 profile 怎么提升 DSH 自身的依赖，它都能挂载成功。

配置因此走环境变量：

| 环境变量 | 默认值 | 含义 |
|---|---|---|
| `DSH_DELETE_ARCHIVED_SESSIONS_ROOT` | `$DSH_HOME/sessions` | 要操作的会话根目录 |
| `DSH_DELETE_ARCHIVED_SESSIONS_TRASH` | `<根目录>/../.deleted-sessions` | 删除时移入的回收站 |
| `DSH_DELETE_ARCHIVED_SESSIONS_PERMANENT` | 不设（允许永久删除） | 设为 `0`、`false` 或 `no` 则禁止永久删除，强制走可恢复路径 |

`$DSH_HOME` 的读取方式和 DSH 本身一致：先看 `$DSH_HOME`，没有就用 `~/.dsh`。
